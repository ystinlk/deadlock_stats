# Проект deadAPI — заметка для себя

## Что это за проект
- Это прежде всего **фронтенд / веб-проект**.
- Ты работаешь с HTML, CSS и JavaScript, создаёшь пользовательский интерфейс и подгружаешь данные из API.
- Это не серверная часть, но уже важно: ты делаешь веб-сервис, который показывает данные игрокам.
- Если ты начнёшь делать работу на сервере, это станет частью пути в **full-stack**.

## Что рефакторить
### 1. Обработка запросов и ошибок
- Добавить `try/catch` вокруг `fetch`.
- Проверять `response.ok` и показывать пользователю понятное сообщение об ошибке.
- Обрабатывать ситуацию, когда API не дал данные или вернул пустой массив.

### 2. Разделение кода на части
- Вынести работу с API в отдельную функцию или модуль (`getHeroes()`, `getLeaderboard(region)`, `searchPlayer(query)`).
- Вынести рендеринг таблицы/списка в отдельную функцию (`renderHeroes()`, `renderLeaderboard()`, `renderSearchResults()`).
- Отдельно готовить данные, отдельно отображать.

### 3. Упрощение и читаемость
- Названия переменных должны отражать смысл:
  - не `data_unSorted`, а `heroRows`
  - не `result`, а `regionLeaderboard`
- Удалить дублирование: стиль кнопок, создание HTML-строк, вычисление цветов и т.п.
- Избегать длинных функций: одна функция = одна задача.

### 4. Пользовательский опыт (UX)
- Добавить индикатор загрузки (`Loading...`).
- Добавить состояние пустого результата (`Ничего не найдено`).
- Проверять пустой ввод в поиске.
- Сделать кнопку `type="button"`, чтобы форма не отправлялась случайно.

### 5. Адаптивность и вёрстка
- Сделать медиазапросы для мобильных экранов.
- Не задавать жёсткие `width: 600px` / `400px` без адаптации.
- Использовать `max-width` и `flex`/`grid`.
- Проверить, как таблицы выглядят на телефоне.

## Советы по обучению
### Текущая ступень
- Ты уже — **junior frontend / веб-разработчик** в стадии обучения.
- Это не плохо, это нормально: ты набираешь опыт на реальном проекте.

### Что изучать дальше
- `async/await` для работы с асинхронным кодом.
- Работа с DOM: `querySelector`, события, рендеринг.
- Основы CSS layout: flexbox, grid, адаптивность.
- Принципы чистого кода: функции должны быть короткими и понятными.
- Работа с API: структура запросов, фильтрация, пагинация, кэш.
- Git: фиксировать изменения, писать понятные коммиты, сохранять прогресс.

### Маленькие цели
- Сделать отдельную страницу героя или игрока.
- Сохранить последний результат в `localStorage`.
- Добавить фильтр на лидерборде.
- Сделать страницу с анализом одного игрока.

## Что делать дальше
### Фронтенд сейчас
- Вывести данные со всех нужных эндпоинтов API.
- Сделать удобный интерфейс и фильтрацию.
- Собрать нормальную структуру кода.

### Серверная часть позже
- Когда фронтенд будет показывать данные, можно перейти к backend:
  - хранение данных на сервере,
  - кэширование ответов,
  - подготовка агрегированных метрик,
  - анализ матчей и расчёт показателей.
- Серверная часть полезна, если API медленный или нужно обрабатывать данные перед отдачей.

## Как себя позиционировать
- Сейчас ты **веб-разработчик**, точнее — **frontend-разработчик**.
- Позже, когда добавишь сервер и анализ, ты будешь двигаться в сторону **full-stack**.
- Если хочешь, можешь называть себя просто: "ученик веб-разработчика" или "фронтенд-разработчик в процессе обучения".

## Итог
- Проект не плохой, он обычный первый проект.
- Он показывает, что ты понимаешь, как работать с API и как строить страницу.
- Рефакторинг нужен, чтобы код стал понятнее и надёжнее.
- Следующий шаг — улучшить фронтенд, а затем пробовать backend-анализ.
